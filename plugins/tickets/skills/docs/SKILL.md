# ドキュメントの置き場所

先に対象リポジトリの `docs/README.md` と既存のディレクトリを見る。リポジトリ固有の地図があるならそれを優先する。以下は `docs/` を情報の性質で分けるときの公開可能な案内で、非公開の規約本文を写したものではない。

## 置き場所

| 内容 | 場所 |
|---|---|
| 実行手順（人が手を動かすもの） | `docs/dev/` |
| 判断の記録（1 判断 1 ファイル、日付つき） | `docs/decisions/` |
| 設計・仕様 | `docs/spec/` |
| 実測・レビュー | `docs/review/` |
| 外部調査 | `docs/research/` |
| 何を作っているか・入れ方 | ルートの `README.md` |
| いま何が残っているか | GitHub Issue |

- リポジトリが既にルートの `dev/` を使っている場合を除き、新しくルートへ `dev/` を作らない
- `status/` や TODO 台帳は増やさない。残っていることは Issue に書く

## 守ること

- 同じ内容を 2 箇所に書かない
- 空のディレクトリは作らない
- 恒常ファイル（`spec/` `dev/`）は kebab-case の英語ファイル名
- 時系列のもの（`decisions/` など）は `YYYY-MM-DD_日本語タイトル.md`
- 公開リポジトリでは、非公開ドキュメントのパスや個人環境のパスを書かない
