# ドキュメントの置き場所

先に対象リポジトリの `docs/README.md` を見る。手順や決定記録の場所が書いてあれば、その種類の置き場所はそこに従う。書いていないときだけ、「置き場所」の順で 1 箇所に決める。

`docs/README.md` に場所があっても外してよいのは、この置き場所の決め方だけである。命名、同じ内容を 2 箇所に書かないこと、空のディレクトリを作らないこと、個人環境のパスを書かないことは、「守ること」として常に適用する。

「置き場所」は、地図が書いていないときの分け方で、非公開の規約本文を写したものではない。

## 置き場所

文書の種類ごとに、次の順で 1 箇所だけに決める。上の段が当たれば、下の段は使わない。

`docs/README.md` がその種類の場所を書いていて、ルートの `dev/` や `DECISIONS.md` もあるときは、`docs/README.md` の場所へ書く。両方あるときにルート側へ移さない。ルート側を優先するのは、`docs/README.md` にその種類の場所が書いていないときだけである。

実行手順（人が手を動かすもの）:

1. `docs/README.md` に手順の場所があるなら、そこへ書く
2. それが無く、ルートに `dev/` があるなら、そこへ書く。`docs/dev/` があってもそこには書かない
3. ルート `dev/` も `docs/README.md` の指定も無く、`docs/dev/` があるなら、そこへ書く
4. どれも無いなら `docs/dev/` を作って書く。ルート `dev/` は作らない

決定記録:

1. `docs/README.md` に決定記録の場所があるなら、そこへ書く
2. それが無く、ルートに `DECISIONS.md` があるなら、そのファイルの既存の書式で足す。`docs/decisions/` があってもそこには書かない
3. ルート `DECISIONS.md` も `docs/README.md` の指定も無く、`docs/decisions/` があるなら、そこへ 1 判断 1 ファイルで足す
4. どれも無いなら `docs/decisions/` を作って書く。ルート `DECISIONS.md` は作らない

ほかの文書は、既存のディレクトリがあればそこへ足す。無ければ次の既定を作る。同じ種類の文書の置き場所を新しく増やさない。

| 内容 | 既定（その種類の既存が無いとき） |
|---|---|
| 実行手順 | `docs/dev/`（ルート `dev/` は作らない） |
| 判断の記録 | `docs/decisions/`（ルート `DECISIONS.md` は作らない） |
| 設計・仕様 | `docs/spec/` |
| 実測・レビュー | `docs/review/` |
| 外部調査 | `docs/research/` |
| 何を作っているか・入れ方 | ルートの `README.md` |
| いま何が残っているか | GitHub Issue |

- `status/` や TODO 台帳は増やさない。残っていることは Issue に書く

## 守ること

- 同じ内容を 2 箇所に書かない
- 空のディレクトリは作らない
- 恒常ファイル（`docs/spec/`、手順を置く `docs/dev/` またはルート `dev/`）は kebab-case の英語ファイル名
- `docs/decisions/` のファイル名は `YYYY-MM-DD_日本語タイトル.md`
- ルート `DECISIONS.md` に足すときは、日付ファイルを増やさず、そのファイルの既存の書式に合わせる
- 公開リポジトリでは、非公開ドキュメントのパスや個人環境のパスを書かない
