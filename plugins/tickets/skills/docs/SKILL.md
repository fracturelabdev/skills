# ドキュメントの置き場所

先に対象リポジトリの `docs/README.md` を見る。手順や決定記録の場所が書いてあればそれに従い、以下は使わない。書いていないときは、すでにある置き場所に足す。同じ種類の文書の置き場所を新しく増やさない。以下は既存が無いときの分け方で、非公開の規約本文を写したものではない。

## 置き場所

実行手順（人が手を動かすもの）は、次の順で 1 箇所に決める。

1. ルートに `dev/` があるなら、手順はそこへ書く。`docs/dev/` があってもそこには書かない
2. ルート `dev/` が無く、`docs/dev/` があるなら、そこへ書く
3. どちらも無いなら `docs/dev/` を作って書く。ルート `dev/` は作らない

決定記録は、次の順で 1 箇所に決める。

1. ルートに `DECISIONS.md` があるなら、そのファイルの既存の書式で足す。`docs/decisions/` があってもそこには書かない
2. ルート `DECISIONS.md` が無く、`docs/decisions/` があるなら、そこへ 1 判断 1 ファイルで足す
3. どちらも無いなら `docs/decisions/` を作って書く。ルート `DECISIONS.md` は作らない

ほかの文書は、既存のディレクトリがあればそこへ足す。無ければ次の既定を作る。

| 内容 | 既定（その種類の既存が無いとき） |
|---|---|
| 実行手順 | `docs/dev/`（ルート `dev/` は作らない） |
| 判断の記録 | `docs/decisions/`（ルート `DECISIONS.md` は作らない） |
| 設計・仕様 | `docs/spec/` |
| 実測・レビュー | `docs/review/` |
| 外部調査 | `docs/research/` |
| 何を作っているか・入れ方 | ルートの `README.md` |
| いま何が残っているか | GitHub Issue |

- `status/` や TODO 台帳は増やさない。残っていることは Issue に書く

## 守ること

- 同じ内容を 2 箇所に書かない
- 空のディレクトリは作らない
- 恒常ファイル（`docs/spec/`、手順を置く `docs/dev/` またはルート `dev/`）は kebab-case の英語ファイル名
- `docs/decisions/` のファイル名は `YYYY-MM-DD_日本語タイトル.md`
- ルート `DECISIONS.md` に足すときは、日付ファイルを増やさず、そのファイルの既存の書式に合わせる
- 公開リポジトリでは、非公開ドキュメントのパスや個人環境のパスを書かない
